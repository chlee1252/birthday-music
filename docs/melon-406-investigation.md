# 멜론 406 조사 (2026-10-25)

## 재현 결과
동일 로컬 네트워크에서 Node fetch와 Chrome 실제 UI로 비교했다. 로그인·쿠키 없이 공개 페이지만 조회했다.

| 요청 | 결과 |
| --- | --- |
| `/search/album/index.htm?section=all&q=PLAY` | 406 |
| section 생략 / 빈 값 / album 값 | 모두 406 |
| Accept를 text/html에서 */*로 변경 | 406 |
| User-Agent를 앱 식별자에서 Mozilla/5.0으로 변경 | 406 |
| 검색어 아이유 | 406 |
| 멜론 폼의 searchGnbYn, kkoSpl, kkoDpType 포함 | 406 |
| Chrome 곡 검색 페이지에서 실제 앨범 탭 클릭 | 같은 페이지 오류 표시 |
| `/search/song/index.htm?section=album&sort=hit&q=PLAY` | 200, AKMU 곡 반환 |
| `/song/detail.htm?songId=4583482` | 200, 2014.04.07 및 실제 커버 |

406 본문은 멜론 공통 HTML 오류 페이지로 “페이지를 찾을 수 없습니다”, “잘못된 경로로 접근 하셨거나, 사용할 수 없는 웹사이트 주소”를 안내한다. 멜론 자체 JS의 goTotalSearch도 동일 `/search/album/index.htm` 경로를 구성한다. 따라서 앱 URL 오타나 단순 Accept/User-Agent 문제라는 근거는 없으며, 현재 환경에서 멜론 자체 앨범 검색 경로의 가용성 문제가 재현된다. 서버 내부 라우팅 오류인지 정책 차단인지는 멜론 서버 로그 없이는 확정할 수 없다. IP 전체 차단이나 로그인 필수라고 단정할 근거도 없다.

## 적용
앨범 검색의 406/404에 한해 멜론 공개 곡 검색의 ‘앨범명에서 보기’로 대체 조회한다. 동일 가수/별칭, 앨범 ID 중복 제거, 곡 상세의 정확한 발매일 검증 후 대표곡과 커버를 채택한다. 앨범 후보당 상세 최대 4개, 동시 2개 제한. 인증 우회나 프록시 변경 없음. 상세 누락은 partial로 유지하며 실패한 상세를 가짜 빈 결과로 처리하지 않는다.

실제 조회: 2014.04.07 당일 200%, 같은 월일 1999/감각/봄바람/두사람, 모두 커버 있음. 1995.11.27 당일 확인된 곡 0개, 같은 월일 10곡 반환(일부 상세 발매일 누락으로 partial). 테스트 37개와 production build 통과.
